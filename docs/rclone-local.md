# Перенос облака Mail.ru в Google Drive со своего компьютера

Инструкция на случай, когда [блокнот для Colab](../mailru_backup_to_drive.ipynb)
не годится. А не годится он часто: Colab **запрещает** использовать свои
машины как перекладчик файлов между облаками, и обрывает сессию с формулировкой
«выполнение кода, недопустимого в бесплатной версии». Массовый `rclone copy`
попадает под запрет — см. [их FAQ](https://research.google.com/colaboratory/faq.html),
раздел про file hosting и media serving.

## Диск при этом не нужен

Главное, что стоит понимать: при перегоне между двумя облаками rclone **не
складывает файлы на диск.** Он открывает поток из источника и тут же пишет его
в приёмник, держа в оперативной памяти буфер на несколько мегабайт. На диске
оседает только сам `rclone.exe`, около 60 МБ.

Расплата другая: весь объём проходит **через твой интернет** — вниз от Mail.ru
и вверх в Google. Узким местом будет исходящий канал, он у домашних тарифов
обычно куда медленнее входящего.

| Твой upload | 13 ГБ пройдут за |
|---|---|
| 10 Мбит/с | ~3 часа |
| 50 Мбит/с | ~35 минут |
| 100 Мбит/с | ~18 минут |

Если совсем медленно — возьми VPS на сутки (у большинства почасовая оплата,
выйдет рублей 50) и проделай то же самое там, на гигабитном канале.

## Что понадобится от Mail.ru

**Пароль для внешних приложений**, а не обычный от почты: настройки Mail.ru →
Безопасность → «Пароли для внешних приложений».

⚠️ При создании выбери **«Полный доступ к Почте, Облаку и Календарю»** — все
протоколы. Вариант «Полный доступ к Облаку (WebDav)» с rclone **не работает**:
вход падает с сообщением «неверный пароль», хотя пароль правильный. Это самая
частая причина отказа.

Если на аккаунте включена двухфакторная аутентификация, rclone войти не сможет
— это его давняя нерешённая проблема. Тогда либо отключи её на время переноса,
либо смотри «План Б» в конце.

И если Mail.ru ограничил доступ за переполнение — нажми в их приложении
«Снять ограничение временно», иначе файлов не будет видно.

## Установка

Ставить нечего — это один exe-файл.

1. Скачай <https://downloads.rclone.org/rclone-current-windows-amd64.zip>
2. Распакуй куда угодно, например в `C:\rclone`
3. Открой в этой папке PowerShell: Shift + правый клик по пустому месту →
   «Открыть окно PowerShell здесь»
4. Проверь, что работает:

```powershell
.\rclone version
```

## Настройка двух облаков

**Не используй интерактивный `rclone config`** — там легко промахнуться, и на
живом прогоне это стоило часа отладки. Для Mail.ru диалог спрашивает
`client_id` **раньше**, чем `user`, а подпись у него «Leave blank normally» —
и адрес почты уезжает в поле для OAuth-ключа. Remote при этом создаётся, но
не работает, а `rclone config update mailru client_id ""` его оттуда **не
убирает**: единственный способ — пересоздать remote целиком.

Поэтому задаём всё сразу командами, без вопросов.

### Mail.ru

```powershell
.\rclone config create mailru mailru user ТВОЙ@internet.ru pass 'ПАРОЛЬ' --obscure
```

Пароль в **одинарных** кавычках — так PowerShell возьмёт его буквально и не
подавится на `$` и других спецсимволах. `--obscure` зашифрует его при записи.

Заданы ровно три поля, `client_id` не появляется вовсе — rclone берёт
встроенный.

```powershell
.\rclone lsd mailru:
```

Должен показать список папок.

### Google Drive

```powershell
.\rclone config create gdrive drive scope drive
```

Откроется браузер — войди и разреши доступ. Если спросит про общий диск
(`Configure this as a Shared Drive (Team Drive)?`) — отвечай `n`, у личного
Drive его нет.

```powershell
.\rclone lsd gdrive:
```

Если токен когда-нибудь протухнет или его придётся заменить:

```powershell
.\rclone config reconnect gdrive:
```

### Две вещи, на которых легко споткнуться

**Вставляй команды по одной.** PowerShell при двойной вставке склеивает их в
одну строку, и получается `--obscure.\rclone config create...` с ошибкой
`unknown flag`. Перед вставкой нажми Esc, чтобы очистить строку, вставь через
Ctrl+V и глазами проверь строку до Enter.

**Не пересылай вывод `config create` и `config reconnect` никому.** Для Drive
они печатают OAuth-токен целиком, включая `refresh_token` — он не истекает сам
и даёт полный доступ ко всему твоему Drive. Если такой вывод куда-то утёк:
отзови доступ на <https://myaccount.google.com/permissions> (пункт `rclone`),
потом `rclone config reconnect gdrive:` — старый токен умрёт, новый будет
рабочим.

### Про предупреждение о client_id

rclone будет писать, что его общий ключ для Google Drive выводят из
эксплуатации и он перестанет работать в течение 2026 года. Сейчас это не
мешает. Когда отключат — придётся
[завести свой ключ](https://rclone.org/drive/#making-your-own-client-id), это
бесплатно и минут на десять.

## Проверка

Если Mail.ru ругается на пароль — вернись к разделу про права выше, дело почти
наверняка в них. Проверь заодно, не спутаны ли в пароле заглавная `I` и
строчная `l`: в большинстве шрифтов они выглядят одинаково, поэтому пароль
надёжнее копировать, а не перепечатывать.

Посмотреть объём, который поедет:

```powershell
.\rclone size mailru:
```

## Пробный прогон

Сначала без копирования — просто посмотреть, что и куда собирается ехать:

```powershell
.\rclone copy mailru: "gdrive:Из Mail.ru Облака" --dry-run --progress
```

## Копирование

```powershell
.\rclone copy mailru: "gdrive:Из Mail.ru Облака" --progress --transfers 4 --retries 5
```

Оборвалось, компьютер уснул, отключился интернет — **просто запусти команду
заново.** rclone сверит, что уже лежит в Drive, и докопирует только
недостающее. Заново всё качать не станет.

Если медленно, попробуй `--transfers 8`. Если после этого полезли ошибки —
Mail.ru придушивает, возвращай на 4.

## Проверка результата

```powershell
.\rclone check mailru: "gdrive:Из Mail.ru Облака" --one-way --size-only
```

Сравнение по размерам, потому что Mail.ru и Google считают контрольные суммы
по-разному, и побайтово сверить не получится.

Скажет `0 differences found` — всё доехало. **Только после этого** чисти
Mail.ru, и делай это руками через их сайт: сначала глазами убедись, что папки
в Drive на месте и открываются. Это твоя единственная копия — ни rclone с
`copy`, ни блокноты из этого репозитория из источника ничего не удаляют.

## Уборка

Пароль осел в истории PowerShell открытым текстом — убери:

```powershell
Clear-History
Remove-Item (Get-PSReadLineOption).HistorySavePath
```

Когда перенос больше не нужен, отзови доступы: пароль для внешних приложений
удали в настройках Mail.ru, доступ rclone к Google — на
<https://myaccount.google.com/permissions>. Локальный конфиг тоже можно
подчистить:

```powershell
.\rclone config delete mailru
.\rclone config delete gdrive
```

## План Б: через публичные ссылки

Если вход так и не удался — двухфакторку отключать не хочется, права пароля
перебрал, а rclone упорно не пускает — есть обход, не требующий авторизации
вообще.

Публичные ссылки Mail.ru отдаются **без входа в аккаунт**, а блокнот
[`mailru_to_drive.ipynb`](../mailru_to_drive.ipynb) умеет по таким ссылкам
качать, и он проверен на живых данных.

1. Открой Mail.ru Облако в браузере
2. Выдели папку → «Получить ссылку»
3. Вставь её в `MAILRU_URL` в блокноте
4. В поле «Что скачивать» поставь **«все файлы»**
5. Пароль архива оставь пустым — распаковывать нечего
6. Выполни все ячейки

Ссылки надо получать руками на каждую папку, всё облако разом так не заберётся
— зато паролей не требуется. Ссылки потом отзываются в том же меню.

Учти, что это тоже Colab, и при большом объёме он может прервать сессию по той
же причине. На отдельных папках обычно проходит.
